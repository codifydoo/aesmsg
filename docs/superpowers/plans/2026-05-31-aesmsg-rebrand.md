# aesmsg Rebrand Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the entire project from `securesend`/`securemsg`/`SecureSend`/`SecureMsg`/`@securesend/*` to the single lowercase brand **`aesmsg`**, including npm scope, display name, behavioral identifiers, dev DB credentials, design artifacts, the crypto public-key wire prefix (`ssk1:`→`amk1:`), the user-visible fingerprint prefix (`SM-`→`AM-`), and the GitHub repository.

**Architecture:** This is a behavior-preserving rename, so it is driven by a small set of **string-class replacements** applied repo-wide (each its own reviewable task) rather than per-feature TDD. The "test" for each task is the existing suite + `pnpm typecheck` + a `grep` residue sweep — we are proving the rename changed nothing semantic. Replacements run **sequentially** (subagent-driven, reviewed between tasks) to avoid the file-conflict risk of parallel sweeps. The one genuinely cryptographic edit (the pubkey prefix) was proven safe in the spec: it touches no authenticated bytes, so **no ciphertext changes and no interop-vector regeneration is required**.

**Tech Stack:** pnpm 10 monorepo, TypeScript (strict), Vitest, Biome 2, Next.js 16 (web), Expo SDK 56 (mobile), `@hpke/core` crypto, `gh` CLI.

**Spec:** [docs/superpowers/specs/2026-05-31-aesmsg-rebrand-design.md](../specs/2026-05-31-aesmsg-rebrand-design.md)

## Conventions used by every task

**Repo root** (run all commands from here):
`/path/to/aesmsg` (the repo root or your worktree)

**Replacement engine:** `perl -pi -e` (macOS-safe in-place edit, no backup file).

**Standard exclusions** — never rewrite these (they document the old→new mapping, are generated, or are intentionally out of scope per spec §6):
- `node_modules`, `.git`
- `.claude/` (skill/workflow files — out of scope; leave name and content untouched)
- `pnpm-lock.yaml` (regenerated by `pnpm install`, not by sed)
- any path matching `*aesmsg-rebrand*` (this plan + the design spec)

**Canonical "find files then replace" idiom** (substitute the pattern per task):
```bash
grep -rIlZ '<SEARCH>' . \
  --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=.claude \
  --exclude=pnpm-lock.yaml --exclude='*aesmsg-rebrand*' \
  | xargs -0 perl -pi -e 's/<SEARCH>/<REPLACE>/g'
```
(`-r` recursive, `-I` skip binary files e.g. the design PNGs, `-l` list filenames, `-Z` NUL-separate for safe `xargs -0`.)

## Task 6: Rename user-visible fingerprint prefix `SM-` → `AM-`

`SM-` (SecureMsg) is the human-facing prefix on rendered fingerprints (`SM-1A2B-…`). It is **NOT confined to a few files** — it appears in ~40 files: the source constant `packages/crypto/src/fingerprint.ts` (`FINGERPRINT_PREFIX`), two mobile *source* files that build/parse the prefix (`apps/mobile/src/settings/settings-format.ts`, `apps/mobile/src/contacts/contacts-display.ts`), and ~37 test fixtures across `packages/crypto`, `packages/ui`, `apps/web/tests`, and `apps/mobile/tests` that hardcode sample fingerprints like `"SM-AAAA-…"`. The hash digits are unchanged (Task 5 proved canonical bytes are stable) and `"AM-"` is the same length as `"SM-"`, so a literal token swap keeps every expected value and every length/offset assumption valid.

**Approach:** repo-wide scoped replacement of the literal `SM-` across `.ts`/`.tsx` files, with the test suite as the backstop.

**Files:** ~40 `.ts`/`.tsx` files under `packages/` and `apps/` (source + tests). Do not enumerate by hand — use the scoped sweep below.

- [ ] **Step 1: Snapshot the `SM-` occurrences (all should be brand fingerprint/key samples)**

```bash
grep -rln 'SM-' --include='*.ts' --include='*.tsx' . --exclude-dir=node_modules --exclude-dir=.git
```
Expected: ~40 files, all under `packages/crypto`, `packages/ui`, `apps/web/tests`, `apps/mobile`. Spot-check a couple of hits to confirm every `SM-` is a brand fingerprint/public-key sample (not an unrelated substring). Note in particular `apps/mobile/tests/qr-matrix.test.ts` (a `"SM-PUB-…"` sample fed to `toQrMatrix`) — see Step 4.

- [ ] **Step 2: Replace the literal `SM-` → `AM-` across source + test files**

```bash
grep -rIlZ 'SM-' --include='*.ts' --include='*.tsx' . \
  --exclude-dir=node_modules --exclude-dir=.git \
  | xargs -0 perl -pi -e 's/SM-/AM-/g'
```

- [ ] **Step 3: Verify the constant flipped and no `SM-` remains**


Expected: `FINGERPRINT_PREFIX = "AM-"`; `CLEAN`.

- [ ] **Step 4: Run the affected suites (full crypto/ui/web/mobile, since fixtures span all four)**

```bash
pnpm --filter @aesmsg/crypto test
pnpm --filter @aesmsg/ui test
pnpm --filter web test
pnpm --filter @aesmsg/mobile test
```
Expected: ALL PASS. **Watch `apps/mobile/tests/qr-matrix.test.ts`:** if it asserts on the exact QR matrix produced from the `SM-PUB-…` input, changing the input to `AM-PUB-…` will change the expected matrix and fail. If so, that is the *correct* new input — regenerate/update that test's expected matrix to match the `AM-PUB-…` sample (the QR encoder is content-agnostic; only the fixture's expected output needs refreshing). Any other failure means a genuine fingerprint value drifted — STOP and investigate.
