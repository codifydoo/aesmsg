# Slice 2 — Browser key store + private-key wrap/unwrap

**Date:** 2026-05-09
**Status:** Draft, awaiting approval
**Author:** Claude (brainstorming session with @dsantic)
**Builds on:** [`2026-05-09-crypto-core-design.md`](2026-05-09-crypto-core-design.md), [`2026-05-09-project-init-design.md`](2026-05-09-project-init-design.md)

## 1. Context

Slice 1 landed the trust foundation: HPKE-based seal/open + identity + fingerprint. The two functions left throwing `NotImplementedError` — `wrapPrivateKey` and `unwrapPrivateKey` — are the bridge between the in-memory `IdentityKeypair` and what stays *at rest* on the user's machine between sessions.

Slice 2 lands those two functions for real, plus a new `@aesmsg/key-store` package that uses them to persist a wrapped private key in IndexedDB. After Slice 2 ships, the web app has everything it needs to remember a user's identity across page loads — gated behind a passphrase the server never sees.

The Slice 1 init spec rule "**No DOM, no network, no storage**" applies to `@aesmsg/crypto`. IndexedDB therefore lives in a sibling package, not inside crypto. Crypto stays portable to React Native, native iOS, native Android — each of which gets its own key-store implementation later (SecureEnclave / StrongBox / etc.) behind the same conceptual interface.

## 2. Goals

- Implement `wrapPrivateKey` and `unwrapPrivateKey` in `@aesmsg/crypto` against Argon2id (KDF) + AES-256-GCM (AEAD).
- Lock a versioned wire format for the wrapped blob so a future KDF rotation does not break old keys.
- Add a `BadPassphraseError` so consumer UIs can show "wrong passphrase" without leaking which check failed for general tamper attempts.
- Ship a new `@aesmsg/key-store` package with a small async API for save / load / has / delete / list — IndexedDB-backed, browser-only.
- Test both packages with the same rigor as Slice 1 (round-trip + negative + interop where applicable). Browser-mode tests for `@aesmsg/key-store` since IndexedDB does not exist in Node.

## 3. Non-goals

- **No UI bootstrap flow.** When to prompt for a passphrase, "no identity yet" detection, error UX — all later-slice concerns.
- **No multi-device sync.** Each device has its own wrapped blob.
- **No forgot-passphrase recovery.** This is an intentional non-feature; the Phase 0 init spec is explicit ("Wrong key → no decryption. No fallbacks, no recovery.").
- **No key rotation.** Phase 2/3 concern.
- **No mobile native key store.** When mobile is chosen, a separate package implements the same conceptual interface against SecureEnclave / StrongBox.
- **No "auto-lock after idle" timer or session-key memory hygiene.** Memory lifetime of an unwrapped key is the consumer's responsibility — `loadIdentity` returns the wrapped blob, the consumer calls `unwrapPrivateKey` when needed.

## 4. KDF and parameters

**KDF:** Argon2id, the OWASP-recommended modern password-hashing primitive. Memory-hard → defeats GPU/ASIC offline brute-force against a stolen wrapped blob, which is the primary at-rest threat.

**Parameters** (OWASP "moderate" profile, tuned for low-frequency wrap/unwrap):

| Parameter | Value | Notes |
|---|---|---|
| `m` (memory cost) | 64 MiB (`65536` KiB) | Hits ~300-800ms on a typical laptop |
| `t` (iterations) | 3 | |
| `p` (parallelism) | 1 | Web Crypto / wasm typically can't use multi-thread anyway |
| Salt | 16 random bytes per wrap | Generated by `crypto.getRandomValues` |
| Output | 32 bytes (used directly as AES-256-GCM key) | |

**AEAD:** AES-256-GCM, 12-byte random IV per wrap, 16-byte authentication tag. Web Crypto handles this natively.

**Library:** [`hash-wasm`](https://github.com/Daninet/hash-wasm) for Argon2id. Adds ~50–100 KB of wasm at first use, cached after that. Works in Node and browser. Pulled in as a runtime dependency of `@aesmsg/crypto`. Cross-implementation interop is not in scope for the wrap path (no other implementation needs to read aesmsg's wrapped blobs — they live only in a aesmsg client's IndexedDB).

## 5. Wrapped-blob wire format

JSON, versioned:

```json
{
  "v": 1,
  "kdf": "argon2id-aes256gcm",
  "m_kib": 65536,
  "t": 3,
  "p": 1,
  "salt": "<base64url, 16 bytes>",
  "iv":   "<base64url, 12 bytes>",
  "ct":   "<base64url, 32 raw priv bytes + 16-byte AEAD tag = 48 bytes>",
  "pub":  "<base64url, 32 raw X25519 pubkey bytes — not secret>"
}
```

`pub` (the raw public key bytes) lives in the envelope in plaintext because (a) the public key is not secret, and (b) `unwrapPrivateKey` needs both halves of the keypair to reconstruct an `IdentityKeypair`, and `@hpke/core` does not expose a "derive pubkey from privkey CryptoKey" API. Storing `pub` here keeps `unwrap` self-contained — no need for the consumer to pass the public key alongside.

JSON over compact bytes because:

- IndexedDB stores strings natively; no extra serialization layer.
- "What's in my key store?" debugging is trivial.
- Size cost (~200 bytes vs ~115 bytes raw) is irrelevant for at-rest data.
- Adding fields later (e.g., a future `kdf` value) requires no schema migration.

`unwrapPrivateKey` rejects, with `InvalidFormatError`:

- Not parseable JSON
- Missing required keys
- Unknown `v`
- Unknown `kdf` value
- Wrong base64url
- Wrong byte lengths after decoding (salt ≠ 16, iv ≠ 12, ct ≠ 48, pub ≠ 32)

`unwrapPrivateKey` throws `BadPassphraseError` (subclass of `DecryptionError`) when the AEAD `open` call fails — that is, the derived wrap key did not match. This is the only signal an attacker can probe for, and they probe it offline against their copy of the wrapped blob. There is no online oracle to defend against, so distinguishing "wrong passphrase" from "tampered ciphertext" at the API level is acceptable for UX. (For `seal`/`open` we still surface a single opaque `DecryptionError` because that path is exposed online via API routes in Slice 3.)

## 6. `@aesmsg/crypto` API changes

```ts
// Slice 2 changes
type WrappedKey = string;  // serialized JSON envelope (was an opaque brand on {} in Phase 0 stubs)

export class BadPassphraseError extends DecryptionError {
  constructor() {
    super("Wrong passphrase");
    this.name = "BadPassphraseError";
  }
}

export async function wrapPrivateKey(
  id: IdentityKeypair,
  passphrase: string,
): Promise<WrappedKey>;

export async function unwrapPrivateKey(
  wrapped: WrappedKey,
  passphrase: string,
): Promise<IdentityKeypair>;
```

Brand-type change: `WrappedKey` was branded `{}` in Phase 0; now branded `string`. Slice 2's first commit updates the brand definition in `types.ts` and the stub signatures accordingly, so the API correction lands cleanly in history.

After Slice 2 ships, `@aesmsg/crypto` has zero `NotImplementedError` paths.

## 7. `@aesmsg/key-store` package

New package at `packages/key-store/`. Browser-only (no Node target). Depends on `@aesmsg/crypto` for the `WrappedKey` and `PublicKeyString` types — never calls into crypto's wrap/unwrap directly. The store stores opaque blobs.

### 7.1 IndexedDB schema

- Database: `aesmsg`
- Database version: 1
- Object store: `identities`
  - keyPath: `identityId` (string)
  - indexes: none initially (small record count, lookup is by primary key)
- One record per identity. Phase 1 always uses `identityId = "primary"`. Phase 3 multi-identity adds more keys.

```ts
interface StoredIdentity {
  identityId: string;            // "primary" for Phase 1
  publicKeyString: PublicKeyString;
  wrapped: WrappedKey;           // the JSON envelope from §5
  createdAt: string;             // ISO 8601 UTC
  label: string;                 // human-friendly, default "My identity"
  schemaVersion: 1;
}
```

`publicKeyString` is cached at the record level so the UI can render "your fingerprint is X" without prompting for the passphrase. The public key isn't sensitive — only the wrapped private key is.

### 7.2 Public API

```ts
export async function saveIdentity(record: StoredIdentity): Promise<void>;
export async function loadIdentity(identityId: string): Promise<StoredIdentity | null>;
export async function hasIdentity(identityId: string): Promise<boolean>;
export async function deleteIdentity(identityId: string): Promise<void>;
export async function listIdentities(): Promise<StoredIdentity[]>;

export class IndexedDBUnavailableError extends Error {}
export class SchemaVersionMismatchError extends Error {}
```

- `saveIdentity` is upsert (create-or-replace). Caller is responsible for not clobbering an existing record unless intentional.
- `loadIdentity` returns `null` for missing, throws on schema mismatch or DB unavailability.
- `listIdentities` returns records ordered by `createdAt` descending. Phase 1 will only see one record; the order matters for Phase 3.
- `hasIdentity` is a fast existence check; does not deserialize the full record.
- `IndexedDBUnavailableError` covers private-browsing modes that disable IndexedDB or browsers without it.
- `SchemaVersionMismatchError` is reserved for future migrations; Slice 2 only writes `schemaVersion: 1`, so this throws on read if the DB contains anything else.

### 7.3 Internals

- The store opens IndexedDB lazily on the first call. Subsequent calls reuse the same connection (singleton).
- All operations go through one `withDB(fn)` helper that opens, runs the transaction, returns the result. No exposed transaction object.
- Upgrade handler: only the v0→v1 migration creates the `identities` object store. Phase 3 will add a v1→v2 migration when multi-identity goes live.
- No external IndexedDB wrapper library (idb, dexie). The native API is verbose but stable, and the surface here is small enough that the abstraction overhead is not worth it.

## 8. Threat model

What Slice 2 defends against:

- **Same-origin XSS reading IndexedDB** — attacker walks away with a wrapped blob; without the passphrase, brute force is gated by Argon2id's memory-hardness (per OWASP, ~$thousands per cracked password at moderate parameters).
- **Local file-system access** (someone with the device, malware copying the browser profile) — same defense.
- **Tampered wrapped blob** — AEAD authenticates; any modification fails `open` with `DecryptionError`.

What Slice 2 does NOT defend against:

- **Memory dump while the app is unlocked** — the unwrapped private key is in JavaScript memory between `unwrapPrivateKey` and end-of-handler. Memory hygiene in JS is best-effort; we don't pursue it in Slice 2.
- **Keylogger capturing the passphrase** — game over, no defense.
- **Modified app code (supply-chain)** — game over. Sproobo deployments + SRI on assets are the eventual mitigation; out of scope.

## 10. Tests

### 10.1 `@aesmsg/crypto` (extends Slice 1's existing suites)

`wrap.test.ts`:

- **Round-trip:** `wrapPrivateKey(id, "pw")` then `unwrapPrivateKey(blob, "pw")` produces an identity that exports to the same `PublicKeyString` and successfully decrypts a fresh ciphertext sealed for that pubkey.
- **Wrong passphrase:** `unwrapPrivateKey(blob, "wrong")` throws `BadPassphraseError`.
- **`BadPassphraseError instanceof DecryptionError`** — Slice 1 callers continue to work.
- **Tampered envelope** (single-byte mutation in `salt`, `iv`, or `ct`) → `DecryptionError`.
- **Malformed JSON** → `InvalidFormatError`.
- **Unknown `v`** (`"v": 999`) → `InvalidFormatError`.
- **Unknown `kdf`** (`"kdf": "scrypt-aes"`) → `InvalidFormatError`.
- **Argon2id determinism KAT:** with a fixed passphrase + fixed salt + fixed params, the wrap key is deterministic. Pin one vector to detect unintended Argon2 parameter drift.
- **Property test (fast-check, 100 iterations):** for any random passphrase + plaintext private-key proxy, wrap + unwrap round-trips.

`stubs.test.ts` is deleted. After Slice 2, no `NotImplementedError` paths remain in the package; the stub-test file's purpose is gone.

Coverage gate: still ≥95% lines on `src/`. The new `wrap.ts` brings new code, but the corresponding tests should keep coverage above the bar.

### 10.2 `@aesmsg/key-store` (browser-mode only)

IndexedDB does not exist in Node. We do **not** pull in `fake-indexeddb`; the truth source is real browser IndexedDB. All key-store tests run via Vitest browser mode (Playwright + headless Chromium, same setup Slice 1 added for crypto).

`identities.test.ts`:

- save → load → bytes equal
- save twice (upsert) → second wins
- load missing → returns `null`
- has(missing) → `false`; has(saved) → `true`
- delete(saved) → load returns `null`
- listIdentities returns descending by createdAt
- multi-identity save (`primary`, `work`) returns both in `listIdentities`

`errors.test.ts`:

- (Best-effort) IndexedDBUnavailableError simulation by stubbing `globalThis.indexedDB = undefined` once and reattaching.
- A pre-seeded record with `schemaVersion: 999` → `SchemaVersionMismatchError`.

Each test starts by deleting the `aesmsg` database to avoid cross-test pollution (handled in a `beforeEach` block).

Coverage gate: ≥95% lines on `src/`.

### 10.3 Cross-package integration test

A small test in `packages/key-store/tests/integration.test.ts` (browser mode):

1. `generateIdentity()` from `@aesmsg/crypto`
2. `wrapPrivateKey(id, "pw")` → JSON envelope string
3. `saveIdentity({ identityId: "primary", publicKeyString, wrapped, createdAt, label, schemaVersion: 1 })`
4. `loadIdentity("primary")` → record
5. `unwrapPrivateKey(record.wrapped, "pw")` → recovered identity
6. `exportPublicKey(recovered)` equals the original public key
7. Round-trip a sealed message against the recovered identity

This exercises the full Slice 2 vertical, end to end.

## 12. Risks and mitigations

- **`hash-wasm` Argon2id wasm download in test runtime.** First-run browser tests may time out on the wasm fetch. Mitigation: configure Vitest browser tests with a generous per-test timeout (60s) the first time wasm is loaded.
- **IndexedDB transaction quirks** (silent abort if a tx is left dangling across an `await`). Mitigation: `withDB` helper structures every operation as one transaction with no awaited gaps; lints/code review catch deviations.
- **Browser quota / storage eviction.** Browsers may evict IndexedDB under storage pressure (Safari is particularly aggressive). Mitigation: out of scope to defend; document in the key-store README that consumers should call `navigator.storage.persist()` for durability, and surface a "your identity may be evicted" hint in a later UX slice.
- **Web Crypto AES-256-GCM IV reuse.** Catastrophic if reused with the same key. Mitigation: every wrap generates a fresh 12-byte random IV via `crypto.getRandomValues`; we never derive an IV from anything.
- **Passphrase entropy.** If the user picks "password123", Argon2id can only do so much. Out of scope for Slice 2; the UI bootstrap slice will handle entropy hints.

## 13. Out of scope for this spec

Anything UI, anything mobile, anything multi-device, anything Phase 3 enterprise. Each gets its own spec.
